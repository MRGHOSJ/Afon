# CLI reference

```
afon [command] [flags]
```

Global (persistent) flags — available on every command:

| Flag | Default | Meaning |
|---|---|---|
| `--kubeconfig` | *(kubeconfig default)* | Path to the kubeconfig file |
| `--context` | *(current context)* | Kubeconfig context name to use |

Exit codes: **0** success · **1** error (validation, apply failure,
Ctrl-C cancellation, `render --check` staleness).

Banners (driver/cluster info) go to **stderr**; `-o json` payloads go to
**stdout**, so redirection stays parseable.

---

## `afon` (root)

> afon inspects Kubernetes clusters

Prints the command list. No behavior of its own.

---

## `afon inspect`

> Probe the cluster and print its profile as text or JSON

Read-only. Creates, modifies, and deletes nothing.

| Flag | Default | Meaning |
|---|---|---|
| `-n, --namespace` | — | Scope/anchor the profile view to a namespace |
| `--full` | off | Include per-item detail the summary collapses |
| `--redact` | off | Mask identifiers and addresses (safe to share) |
| `-o, --output` | `text` | `text` or `json` |

```bash
afon inspect
afon inspect --context k3d-dev -n hello --redact
afon inspect -o json > profile.json
```

See [Cluster profile](../concepts/cluster-profile.md).

## `afon validate`

> Parse and compile a flow file without touching a driver

Checks: YAML shape, `apiVersion`/`kind`, metadata, node ids/types,
per-node config validation (strict — unknown fields rejected), `${...}`
reference resolution against declared outputs, and cycle detection.
Errors carry `file:line:col`.

| Flag | Default | Meaning |
|---|---|---|
| `-f, --file` | `flow.yaml` | Path to the flow file |

```bash
afon validate -f flow.yaml
```

## `afon render`

> Run action nodes and write materialized outputs to files

Runs action nodes that declare an `out:` path (e.g. `app-manifests`)
and writes their output with a provenance header
(`# Generated by afon render`). `plan` and `apply` read the file as-is —
they never re-render implicitly.

| Flag | Default | Meaning |
|---|---|---|
| `-f, --file` | `flow.yaml` | Path to the flow file |
| `--node` | — | Render only this node plus its action ancestors |
| `--all` | off | Render every materializable node |
| `--force` | off | Overwrite hand-edited / non-Afon files |
| `--check` | off | Compare only; **exit 1** if stale (prints would-be content) |
| `--out` | — | Write to this path instead of the node's `out:` |

```bash
afon render -f flow.yaml
afon render -f flow.yaml --check     # CI gate
afon render -f flow.yaml --force     # take back an edited file
```

Refusal messages are intentional: an edited `generated.yaml` is never
clobbered without `--force`.

## `afon plan`

> Show what an apply would do, without executing anything

Side-effect-free by construction. May call `git ls-remote` to resolve
cache inputs (network failures degrade to `will-run` with the reason).

| Flag | Default | Meaning |
|---|---|---|
| `-f, --file` | `flow.yaml` | Path to the flow file |
| `--driver` | `fake` | `fake` or `k8s` |
| `--state-dir` | *(flow file's dir)* | State directory (cache, fake state) |
| `--parallelism` | `4` | Maximum concurrent nodes (execution hint for apply) |
| `--force-conflicts` | off | Take field ownership on SSA conflicts (affects dry-runs too) |
| `--no-prune` | off | Do not plan deletion of objects removed from the flow |
| `-o, --output` | `text` | `text` or `json` |

```bash
afon plan -f flow.yaml
afon plan -f flow.yaml --driver k8s --context k3d-dev
afon plan -f flow.yaml -o json
```

Statuses: `will-run`, `cached`, `create`, `update`, `none`,
`known-after-apply` — see [Plans](../concepts/plans.md).

## `afon apply`

> Execute a flow: re-plan, then run against the driver

Re-plans internally, then executes. Writes a release record (k8s
driver), waits for readiness, prunes removed objects (owner-scoped),
and prompts before deletes.

**All `plan` flags**, plus:

| Flag | Default | Meaning |
|---|---|---|
| `--show-rendered` | off | Print known action outputs to stderr before executing |
| `--auto-approve` | off | Skip the delete-confirmation prompt |
| `--no-wait` | off | Do not wait for created/updated objects to become ready |
| `--wait-timeout` | `5m` | Readiness wait limit (`0` = wait indefinitely) |
| `--takeover` | off | Supersede a **stale** (>10 min) pending record; fresh ones still block |

```bash
afon apply -f flow.yaml --driver k8s --context k3d-dev
afon apply -f flow.yaml --driver k8s --context k3d-dev --auto-approve --no-wait
```

Failure semantics: a failed node halts scheduling; with
`onFailure: rollback` the run auto-rolls-back. Ctrl-C → `cancelled`
nodes, terminal `failed` record, exit 1.

## `afon history`

> List this flow's release records, newest first

| Flag | Default | Meaning |
|---|---|---|
| `-f, --file` | `flow.yaml` | Path to the flow file |
| `--driver` | `fake` | `fake` or `k8s` (records exist only for `k8s`) |
| `-o, --output` | `text` | `text` or `json` |

```bash
afon history -f flow.yaml --driver k8s --context k3d-dev
```

```
SEQ  STATUS     TRIGGER  AGE  OBJECTS
7    succeeded  manual   23h  2
6    failed     manual   23h  0
```

Keeps the newest 10 records per flow.

---

## `afon status`

> Compare live cluster state against the latest release record

Anchors on the **newest** record: compares its inventory hashes against
live objects. Exit **0** when they match.

| Flag | Default | Meaning |
|---|---|---|
| `-f, --file` | `flow.yaml` | Path to the flow file |
| `--driver` | `fake` | `fake` or `k8s` |
| `-o, --output` | `text` | `text` or `json` |

```bash
afon status -f flow.yaml --driver k8s --context k3d-dev
# release v7: succeeded (manual, started 23h ago)
#   ok 2
```

## `afon rollback`

> re-apply an earlier release's recorded manifests

Replays the target release's **recorded manifests exactly as applied**
(does not re-render the flow), prunes what that release doesn't own, and
records the result as a **new** release (append-only). Requires
`--driver k8s`.

**All `plan` flags**, plus:

| Flag | Default | Meaning |
|---|---|---|
| `--to` | *previous release* | Release sequence to replay (see `history`) |
| `--auto-approve` | off | Skip the delete-confirmation prompt |
| `--no-wait` | off | Do not wait for restored objects to become ready |
| `--wait-timeout` | `5m` | Readiness wait limit (`0` = wait indefinitely) |
| `--takeover` | off | Supersede a stale pending record |

```bash
afon rollback -f flow.yaml --driver k8s --context k3d-dev
afon rollback -f flow.yaml --driver k8s --context k3d-dev --to 5
```

**Limits:** does not undo database migrations, volume contents, CRD
schema changes, or other effects outside the cluster.

## Flag interactions worth knowing

- `--context` (global) overrides `spec.target.context` in the flow.
- `--driver` is **never** read from the flow file — you always say where
  execution happens.
- `--state-dir` moves cache + fake state; default is the flow file's
  directory (never the cwd).
- `--force-conflicts` affects plan dry-runs too (the plan must reflect
  what apply would do).
- `--no-prune` affects plan and apply symmetrically.
- `--auto-approve` is a no-op when the plan contains no deletes.
- `--takeover` only crosses the 10-minute stale-pending window; fresh
  pending records always block (concurrency guard).
